# Headless (Scala.js) use: bundle, archives, workers, includes, evolution fixes

Status: implemented (2026-10-19), on top of baboon `b280ac33`. Scope: loading a `:scheme` archive in
a browser and transcoding binary envelopes with `decodeEnvelopeLoaded`, plus the compiler defects met
on the way. Publishing the Scala.js package is out of scope.

## One-file bundle

`ModuleSplitStyle.SmallestModules` linked ~2,300 modules. Both link modes now use `FewestModules`:
`fullLinkJS` emits one `main.js` (21 MB, plus its source map). `test-js-npm` fails if the bundle is
more than one `.js` file.

## SHA-256 on Scala.js

izumi 1.3.0-M4 hashes with a portable FIPS 180-4 implementation (`IzSha256`), so no host global is
read. The node shim in `npm-template/index.js` and the playground's `js-sha256` polyfill are gone;
`worker-acceptance.mjs` loads an archive with `globalThis.sha256` undefined.

Upgrade notes (1.2.25 -> 1.3.0-M4): `Subcontext`/`makeSubcontext` take an effect type (`Identity`
here: the subcontexts bind no effects); `QuasiIORunner.run` is `runBlocking`. Two test-only
workarounds for testkit regressions (zio on the test classpath, 7mind/izumi#2366; a `TagK` binding
for `Either`, 7mind/izumi#2367) are described in `CLAUDE.md`. `deps.lock.json` was regenerated with
`squish-lockfile`; `nix build .#baboon-jvm` passes against it.

## Schema archives: `.bsm`, deflate

The archive format is named *Baboon schema archive*, conventionally `*.bsm`; the CLI flag stays
`--zip-output`, since the file is still a ZIP. `loadMany` accepts deflated entries (method 8) besides
stored ones, so `zip -r` output loads. `util/Inflate.scala` is a pure-Scala RFC 1951 decoder (a port
of zlib's `puff.c`), strict about declared sizes and trailing bytes, tested against
`java.util.zip.Deflater` at every level and strategy. The writer still emits stored, deterministic
archives.

## `loadMany` cost, and Web Workers

Profiling (JFR on the JVM, `--cpu-prof` on node) found three superlinear costs, all fixed without
changing generated code (all 4,512 generated files of the shared model dir and the evolution
metadata are identical before and after; the metadata's version lists come out in another, still
deterministic, order). Deep ids are persisted in model lockfile signatures, so the lockfile hashing
scheme moves to 3: a lockfile signed by an older compiler is re-signed on its first run, without
drift enforcement for that run (the existing scheme-migration path):

- `deepSchemaRepr` expanded every dependency inline, so the expansion grew with the number of paths
  through the dependency DAG. A type that reaches no cycle now contributes a memoized digest.
- `ExtendedRawDefn.parentOf` re-mapped the whole parent scope tree on every name lookup; the tree
  is now mapped once per domain.
- `scala.util.parsing.input.OffsetPosition` rebuilds its line index for every position on Scala.js
  (its index cache is a no-op there); positions now come from one `LineIndex` per source, and the
  `scala-parser-combinators` dependency is gone.

Synthetic model (8 versions, 233–247 types each; `scripts/gen-big-model.py`):
`loadMany` in node 127 s -> 14 s; JVM typing ~6.8 s -> ~1.7 s.

Loading stays synchronous, so the npm package now makes worker use a drop-in: `worker.js` (module
worker entry), `worker-client.js` (`connectBaboonWorker(port)`: every `BaboonCompiler` method as a
Promise, plus `release`; models stay in the worker behind opaque handles; the main thread never loads
`main.js`) and `worker-server.js` (`serveBaboon(port)`). Verified with node `worker_threads`, with
Deno's module `Worker` running `worker.js`, and with a Vite build of the README's recipe run under
Deno.

## Include resolution

`include "p"` resolves next to the including file first; otherwise against the model roots
(`--model-dir`, the archive root for `loadMany`, the inputs' directories for JS `load`). Several
roots holding `p` is an `IncludeAmbiguous` error (it used to be the first root in `Set` order).
`IncludeNotFound` now names the include statement's position and every location tried. A file next
to the including one shadows a root-level file of the same relative path.

## Missing `--model-dir`

Checked once in `main`, before any mode (only the compiler mode checked before; `:scheme`, `:diff`
and `:bincompat` threw `NoSuchFileException`; 7mind/baboon#100). A path starting with `~` gets a
hint about shell expansion.

## Foreign types across versions

`BaboonComparator.diff` had no `(Foreign, Foreign)` case, so any change to a foreign declaration
crashed with `BABOON BUG!!! Mismatching type defs`, as did any change of a type's kind
(7mind/baboon#101). Now:

- `rt` may change and language bindings may be added or removed (`TypedefDiff.ForeignDiff`); no
  conversion is needed, since every language bound in both versions keeps its native type and
  generated conversions copy foreign values as they are;
- a binding changed in place is `ForeignBindingChanged` (a host conversion would copy a value of the
  old native type into the new one);
- a change of kind is `TypeKindChanged`.

`DerivationFailure.Foreign` is no longer produced (only its metadata encoder refers to it).
